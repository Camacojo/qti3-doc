**Operators** are expressions that take one or more sub-expressions as operands and combine their values into a single result. They form the working vocabulary of response processing: comparing a candidate's response to the correct answer, doing arithmetic on scores, and testing membership in containers all happen through operators.

## Purpose

Use an operator whenever a rule needs to *derive* a value from other values rather than simply read one. Operators nest freely, so the operand of one operator is typically another expression such as `qti-variable`, `qti-correct`, `qti-base-value`, or another operator.

- **Logical** operators build the boolean conditions used by `qti-response-if` and related rules.
- **Comparison** operators test one value against another and yield a single boolean.
- **Arithmetic** operators compute numeric results, most often to build a `SCORE`.
- **Container and string** operators inspect multi-valued responses and text.

Operators propagate NULL: if a required operand is NULL, most operators return NULL rather than a value. Test for this with `qti-is-null` before relying on a result.

## Example

<Example title="Combining operators to score a numeric response">

```xml
<qti-response-condition>
  <qti-response-if>
    <qti-and>
      <qti-gte>
        <qti-variable identifier="RESPONSE"/>
        <qti-base-value base-type="float">0.5</qti-base-value>
      </qti-gte>
      <qti-lt>
        <qti-variable identifier="RESPONSE"/>
        <qti-base-value base-type="float">1.5</qti-base-value>
      </qti-lt>
    </qti-and>
    <qti-set-outcome-value identifier="SCORE">
      <qti-base-value base-type="float">1</qti-base-value>
    </qti-set-outcome-value>
  </qti-response-if>
  <qti-response-else>
    <qti-set-outcome-value identifier="SCORE">
      <qti-base-value base-type="float">0</qti-base-value>
    </qti-set-outcome-value>
  </qti-response-else>
</qti-response-condition>
```

</Example>
