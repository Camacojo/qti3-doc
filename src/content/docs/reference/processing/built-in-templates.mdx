QTI 3.0 defines a small set of standard response processing templates that cover the most common scoring patterns. Instead of writing out the response processing rules by hand, you reference a template by its URI on the <code>template</code> attribute of `qti-response-processing`. A conforming engine then applies the well-known logic that the URI stands for.

## Purpose

Built-in templates let you score an item without authoring any explicit rules. You declare a response variable, provide a `qti-correct-response` (and optionally a `qti-mapping` or `qti-area-mapping`), and point the item's response processing at the appropriate template.

Use a built-in template when your scoring follows one of these standard shapes:

- **match_correct** — all-or-nothing scoring. The candidate earns full marks only if the submitted response exactly matches the declared correct response; otherwise the score is zero. Best for single-answer questions and any item where partial credit is not wanted.
- **map_response** — partial credit driven by a `qti-mapping` on the response declaration. Each possible response value carries a `mapped-value`; the outcome is the sum of the mapped values for the selected/entered values. Best for multiple-response choice items and text entry where individual answers carry different weights.
- **map_response_point** — partial credit for point-based responses, driven by a `qti-area-mapping` on the response declaration. Points that fall inside defined areas contribute their mapped values. Best for `qti-select-point-interaction` and other point-typed graphic responses.

When your scoring goes beyond these patterns, write custom rules inside `qti-response-processing` instead of referencing a template.

## Place in the hierarchy

These templates are not elements; they are URIs supplied to the `template` attribute of `qti-response-processing`, which lives inside `qti-assessment-item`. The full template URIs are:

- `https://purl.imsglobal.org/spec/qti/v3p0/rptemplates/match_correct.xml`
- `https://purl.imsglobal.org/spec/qti/v3p0/rptemplates/map_response.xml`
- `https://purl.imsglobal.org/spec/qti/v3p0/rptemplates/map_response_point.xml`

Each template operates on the item's declared variables by convention:

- **match_correct** reads the response variable named <code>RESPONSE</code> and its `qti-correct-response`, then sets the outcome variable named <code>SCORE</code> (1.0 on a match, 0.0 otherwise).
- **map_response** reads <code>RESPONSE</code> and its `qti-mapping`, then sets <code>SCORE</code>.
- **map_response_point** reads <code>RESPONSE</code> and its `qti-area-mapping`, then sets <code>SCORE</code>.

Because the templates rely on these conventional variable names, your item must declare a response variable named `RESPONSE` and an outcome variable named `SCORE` for the standard templates to work.

## Attributes

The `template` attribute is the single attribute you set to invoke a built-in template. It belongs to `qti-response-processing`.

## Example

The three templates side by side — each pairs a response declaration with the
matching `template` URI:

<Tabs>
  <TabItem label="match_correct">
```xml
<qti-response-declaration identifier="RESPONSE" cardinality="single" base-type="identifier">
  <qti-correct-response>
    <qti-value>ChoiceA</qti-value>
  </qti-correct-response>
</qti-response-declaration>

<qti-outcome-declaration identifier="SCORE" cardinality="single" base-type="float">
  <qti-default-value>
    <qti-value>0</qti-value>
  </qti-default-value>
</qti-outcome-declaration>

<qti-response-processing
  template="https://purl.imsglobal.org/spec/qti/v3p0/rptemplates/match_correct.xml"/>
```
_All-or-nothing: full marks only when `RESPONSE` equals the correct response._
  </TabItem>
  <TabItem label="map_response">
```xml
<qti-response-declaration identifier="RESPONSE" cardinality="multiple" base-type="identifier">
  <qti-correct-response>
    <qti-value>A</qti-value>
    <qti-value>C</qti-value>
  </qti-correct-response>
  <qti-mapping default-value="0" lower-bound="0" upper-bound="2">
    <qti-map-entry map-key="A" mapped-value="1"/>
    <qti-map-entry map-key="B" mapped-value="-1"/>
    <qti-map-entry map-key="C" mapped-value="1"/>
  </qti-mapping>
</qti-response-declaration>

<qti-outcome-declaration identifier="SCORE" cardinality="single" base-type="float">
  <qti-default-value>
    <qti-value>0</qti-value>
  </qti-default-value>
</qti-outcome-declaration>

<qti-response-processing
  template="https://purl.imsglobal.org/spec/qti/v3p0/rptemplates/map_response.xml"/>
```
_Partial credit: sums the `mapped-value` of each selected value (clamped to the bounds)._
  </TabItem>
  <TabItem label="map_response_point">
```xml
<qti-response-declaration identifier="RESPONSE" cardinality="single" base-type="point">
  <qti-area-mapping default-value="0">
    <qti-area-map-entry shape="circle" coords="100,100,20" mapped-value="1"/>
  </qti-area-mapping>
</qti-response-declaration>

<qti-outcome-declaration identifier="SCORE" cardinality="single" base-type="float">
  <qti-default-value>
    <qti-value>0</qti-value>
  </qti-default-value>
</qti-outcome-declaration>

<qti-response-processing
  template="https://purl.imsglobal.org/spec/qti/v3p0/rptemplates/map_response_point.xml"/>
```
_Partial credit for point responses: points inside a mapped area score its value._
  </TabItem>
</Tabs>
