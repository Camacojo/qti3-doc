`qti-template-processing` runs **once, when an item is instantiated**, to assign
values to its [template variables](/reference/processing/template-declaration/).
This is how one authored item produces many **variants** (clones): pick random
numbers, choose a scenario, then present and score that specific instance.

## When it runs

Unlike [response processing](/concepts/response-processing/) (which runs after the
candidate answers), template processing runs *before* the item is shown. The
values it sets can be printed in content with
[`qti-printed-variable`](/reference/content/printed-variable/) and used by
response processing to score the variant.

## The rules

- `qti-set-template-value` — assign a value to a template variable.
- `qti-template-condition` (with `qti-template-if` / `qti-template-else-if` /
  `qti-template-else`) — branch based on an [expression](/reference/processing/expressions/).
- `qti-template-constraint` — reject a generated combination and regenerate (e.g.
  avoid a divide-by-zero).
- `qti-set-default-value` / `qti-set-correct-response` — adjust an item's default
  value or correct response for this variant.
- `qti-exit-template` — stop processing.

## Example

<Example title="Pick two random operands for a sum">
```xml
<qti-template-processing>
  <qti-set-template-value identifier="A">
    <qti-random-integer min="2" max="9"/>
  </qti-set-template-value>
  <qti-set-template-value identifier="B">
    <qti-random-integer min="2" max="9"/>
  </qti-set-template-value>
</qti-template-processing>
```
</Example>
