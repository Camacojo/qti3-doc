Response rules are the imperative statements that make up the body of [response processing](/reference/processing/response-processing/). Where [expressions and operators](/reference/processing/expressions/) compute values, rules decide **what happens**: they branch on conditions, assign values to outcome variables, and can stop processing early. A rule sub-tree combines rules (the control flow) with expressions (the values those rules act on).

## Purpose

Use response rules to turn a candidate's captured responses into outcome values such as `SCORE` and `FEEDBACK`. The main rules are:

- **`qti-response-condition`** — the `if / else-if / else` branching construct. It contains one `qti-response-if`, zero or more `qti-response-else-if`, and an optional `qti-response-else`.
- **`qti-set-outcome-value`** — assigns the result of a contained expression to a named outcome variable (for example, setting `SCORE`).
- **`qti-lookup-outcome-value`** — sets an outcome variable by looking a value up in the interpolation or match table declared on that outcome.
- **`qti-exit-response`** — stops response processing immediately; any rules after it are not evaluated.
- **`qti-response-processing-fragment`** — an inline container that groups a reusable sequence of rules, typically expanded from a shared [response-processing template](/reference/processing/built-in-templates/).

## Place in the hierarchy

Response rules appear directly inside [`qti-response-processing`](/reference/processing/response-processing/), and inside the branch containers of a `qti-response-condition`:

- `qti-response-condition` holds `qti-response-if` → (optional) `qti-response-else-if`(s) → (optional) `qti-response-else`.
- `qti-response-if` and `qti-response-else-if` begin with a single boolean [expression](/reference/processing/expressions/) (its condition), followed by the rules to run when that condition is `true`.
- `qti-response-else` holds only rules (no condition).
- `qti-set-outcome-value`, `qti-lookup-outcome-value`, `qti-exit-response`, and `qti-response-processing-fragment` are leaf/sequence rules that may appear at the top level of response processing or nested inside any branch.

Rules that assign values (`qti-set-outcome-value`, `qti-lookup-outcome-value`) reference an [outcome variable](/reference/processing/outcome-declaration/) by its `identifier`; the values they read typically come from [response variables](/reference/processing/response-declaration/) via expressions and operators.

## Rule reference

| Rule | Description |
| ---- | ----------- |
| `qti-response-condition` | Branching construct. Contains one `qti-response-if`, zero or more `qti-response-else-if`, and an optional `qti-response-else`. The first branch whose condition is `true` runs; if none match, the `qti-response-else` runs. |
| `qti-response-if` | First branch of a condition. Starts with one boolean expression; if it evaluates to `true`, the rules that follow are executed. |
| `qti-response-else-if` | Additional branch, evaluated only if all preceding branches were `false`. Also starts with a single boolean expression followed by rules. |
| `qti-response-else` | Fallback branch containing only rules (no condition). Runs when no `if`/`else-if` condition matched. |
| `qti-set-outcome-value` | Assigns the value of its contained expression to the outcome variable named by its `identifier` attribute. |
| `qti-lookup-outcome-value` | Sets the outcome variable named by `identifier` using the interpolation or match table declared on that outcome, indexed by the contained expression. |
| `qti-exit-response` | Terminates response processing immediately. No attributes; any rules after it are skipped. |
| `qti-response-processing-fragment` | Groups a reusable sequence of response rules, commonly used when expanding a shared response-processing template. |

Note that `qti-set-outcome-value` and `qti-lookup-outcome-value` carry a required `identifier` attribute naming the target outcome variable.

## Example

<Example title="A response-condition assigning SCORE with a fallback">

```xml
<qti-response-processing>
  <qti-response-condition>
    <qti-response-if>
      <qti-match>
        <qti-variable identifier="RESPONSE"/>
        <qti-correct identifier="RESPONSE"/>
      </qti-match>
      <qti-set-outcome-value identifier="SCORE">
        <qti-base-value base-type="float">1.0</qti-base-value>
      </qti-set-outcome-value>
    </qti-response-if>
    <qti-response-else>
      <qti-set-outcome-value identifier="SCORE">
        <qti-base-value base-type="float">0.0</qti-base-value>
      </qti-set-outcome-value>
    </qti-response-else>
  </qti-response-condition>
</qti-response-processing>
```

</Example>
