`qti-outcome-processing` is the **test-level** counterpart of
[response processing](/concepts/response-processing/). It runs after items are
scored and combines their [outcomes](/concepts/outcomes-and-scoring/) into
test-level outcomes — most commonly summing every item `SCORE` into a test total.

## Place in the hierarchy

A child of [`qti-assessment-test`](/reference/test/assessment-test/), after the
test parts. It reads item outcomes and writes the test's
[outcome variables](/reference/processing/outcome-declaration/).

## The rules

Outcome processing uses the same shape as response processing:

- `qti-outcome-condition` (with `qti-outcome-if` / `qti-outcome-else`) — branch on
  an [expression](/reference/processing/expressions/).
- `qti-set-outcome-value` — assign a test outcome.
- `qti-exit-test` — stop processing.

The key expression is `qti-test-variables`, which gathers a named variable across
all items (optionally applying a [weight](/reference/test/weight/)); wrap it in
[`qti-sum`](/reference/processing/operators/) to total it.

## Example

<Example title="Sum every item SCORE into the test SCORE">
```xml
<qti-outcome-processing>
  <qti-set-outcome-value identifier="SCORE">
    <qti-sum>
      <qti-test-variables variable-identifier="SCORE"/>
    </qti-sum>
  </qti-set-outcome-value>
</qti-outcome-processing>
```
</Example>
