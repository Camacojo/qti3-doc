The `qti-text-entry-interaction` presents a single-line text box that the candidate fills in with a short free-text response. It is rendered inline, flowing within surrounding text, which makes it the natural choice for fill-in-the-blank questions.

## Purpose

Use `qti-text-entry-interaction` when you need a short, constrained typed answer embedded in a sentence or expression.

- Fill-in-the-blank items where a missing word or value is typed into the sentence.
- Short numeric or single-word answers, such as a computed result or a term.
- Cases where a single line of input is sufficient. For longer, multi-line responses use the [qti-extended-text-interaction](/reference/interactions/extended-text-interaction/) instead.

Because it is an inline interaction, several text-entry boxes can appear within the same block of running text.

## Place in the hierarchy

The interaction lives inside the item body, typically nested within block or inline content such as an HTML `<p>` paragraph (QTI 3.0 item bodies use standard HTML elements directly). It has no child choice elements; the candidate simply types into the box.

It binds to a [qti-response-declaration](/reference/processing/response-declaration/) whose `identifier` matches the interaction's `response-identifier`. The bound response declaration has cardinality `single` and a base type of `string` (or `integer` / `float` when a numeric answer is expected).

## Example

<Tabs>
  <TabItem label="Text answer">
```xml
<qti-response-declaration identifier="RESPONSE" cardinality="single" base-type="string">
  <qti-correct-response>
    <qti-value>Paris</qti-value>
  </qti-correct-response>
  <qti-mapping default-value="0">
    <qti-map-entry map-key="Paris" mapped-value="1"/>
    <qti-map-entry map-key="paris" mapped-value="1"/>
  </qti-mapping>
</qti-response-declaration>

<qti-item-body>
  <p>
    The capital of France is
    <qti-text-entry-interaction response-identifier="RESPONSE"
      expected-length="15" placeholder-text="type a city"/>.
  </p>
</qti-item-body>
```
The `qti-mapping` lets `map_response` accept several spellings. For one exact answer, use the `match_correct` template instead.
    <QtiDemo markup={`
      <p>The capital of France is <qti-text-entry-interaction response-identifier="RESPONSE" expected-length="15" placeholder-text="type a city"></qti-text-entry-interaction>.</p>
    `} />
  </TabItem>
  <TabItem label="Numeric answer">
```xml
<qti-response-declaration identifier="RESPONSE" cardinality="single" base-type="integer">
  <qti-correct-response>
    <qti-value>96</qti-value>
  </qti-correct-response>
</qti-response-declaration>

<qti-item-body>
  <p>
    What is 12 × 8?
    <qti-text-entry-interaction response-identifier="RESPONSE" expected-length="4"/>
  </p>
</qti-item-body>
```
With a numeric base type, score it with the `match_correct` template — no mapping needed.
    <QtiDemo markup={`
      <p>What is 12 × 8? <qti-text-entry-interaction response-identifier="RESPONSE" expected-length="4"></qti-text-entry-interaction></p>
    `} />
  </TabItem>
</Tabs>
