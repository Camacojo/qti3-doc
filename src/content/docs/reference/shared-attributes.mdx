Element reference pages on this site list only the attributes **specific** to
that element. On top of those, QTI 3.0 defines a set of generic attributes that
interactions and most body/content elements inherit from a common base. This
page documents that shared set once, so the individual pages don't have to
repeat it.

## The shared set

Two open-ended groups come on top of the table above:

- **ARIA attributes** — `role` and the full set of `aria-*` attributes
  (`aria-label`, `aria-describedby`, `aria-hidden`, `aria-live`, …) are allowed
  on these elements, exactly as in HTML. Delivery engines pass them through to
  the rendered output. See [accessibility](/concepts/accessibility/) for when
  to reach for ARIA versus a catalog.
- **`data-*` extension attributes** — arbitrary `data-` prefixed attributes are
  allowed as an extension point. Some interactions define their own documented
  ones (e.g. `data-max-selections-message` on
  [choice](/reference/interactions/choice-interaction/)); anything else is
  tool-specific and travels through conforming systems untouched.

## Interactions: `response-identifier`

Every interaction additionally carries the **required** `response-identifier`
attribute, binding it to the
[response declaration](/reference/processing/response-declaration/) that holds
the candidate's answer. It is listed on each interaction page because it is
required, but it works identically everywhere.

## Which elements take the shared set

- **All interactions**, including
  [portable custom interactions](/reference/interactions/custom-interaction/).
- **Most body/content elements**: the HTML content of the
  [item body](/concepts/item-body/), choice/child elements such as
  `qti-simple-choice`, `qti-gap-text` and `qti-hottext`, and content elements
  such as [feedback block and inline](/reference/content/feedback-block-and-inline/),
  [rubric-block](/reference/content/rubric-block/) and
  [prompt](/reference/content/prompt/).

A few content elements carry only their own attribute sets instead:
[qti-modal-feedback](/reference/content/modal-feedback/),
[qti-stylesheet](/reference/content/stylesheet/) and
[qti-printed-variable](/reference/content/printed-variable/) (the latter does
take `id`, `class` and `label`). Elements outside the item body — test
structure, variable declarations, processing rules and packaging — have their
own attribute vocabularies, documented on their pages.

## Example

<Example title="Shared attributes in use">
```xml
<qti-choice-interaction
    response-identifier="RESPONSE"
    max-choices="1"
    id="q1-interaction"
    class="qti-orientation-horizontal"
    lang="en"
    aria-label="Question 1">
  <qti-prompt>Which planet is closest to the Sun?</qti-prompt>
  <qti-simple-choice identifier="A" data-catalog-idref="cat-mercury">Mercury</qti-simple-choice>
  <qti-simple-choice identifier="B">Venus</qti-simple-choice>
</qti-choice-interaction>
```
</Example>
