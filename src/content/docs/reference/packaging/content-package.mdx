A QTI **content package** is an [IMS Content Packaging](/concepts/content-packaging/) ZIP archive that bundles one or more assessment items and/or tests together with an `imsmanifest.xml` file and any supporting media. It is the standard container for moving QTI content between authoring tools, item banks, and delivery systems.

## Purpose

Use a content package whenever QTI content has to be exchanged as a single, self-describing unit rather than as loose XML files.

- Export items and tests from one system and import them into another.
- Deliver a complete test, its sections, and every referenced item as one file.
- Ship media assets (images, audio, video, stylesheets) alongside the XML that references them, keeping relative paths intact.

The package is an ordinary ZIP file. Its defining feature is that the ZIP root always contains a manifest named exactly `imsmanifest.xml`, which lists every file in the package and classifies each unit of content by resource type.

## Place in the hierarchy

- **The archive:** a ZIP file. A package with the manifest at the root is a *Package Interchange File* (PIF); the `.zip` extension is conventional.
- **The manifest:** [`imsmanifest.xml`](/reference/packaging/imsmanifest/) sits at the root and is the entry point. Everything else in the package is discovered through it.
- **Resources:** the manifest declares a `<resource>` for each item, test, or supporting file, giving its `type`, a unique `identifier`, and the `href` of its primary file. Common QTI 3.0 resource types are:
  - `imsqti_item_xmlv3p0` &mdash; a single [assessment item](/concepts/assessment-item/).
  - `imsqti_test_xmlv3p0` &mdash; an [assessment test](/concepts/assessment-test-and-sections/) (which in turn references its item resources).
  - Non-QTI files such as images or stylesheets are declared with generic web-content types (for example `webcontent`) and referenced by the items or tests that use them.
- **Metadata:** each resource may carry [metadata](/reference/packaging/metadata/) (LOM plus QTI-specific metadata) describing the content for discovery and cataloguing.

A typical package that contains one test and two items looks like this:

```
my-package.zip
├── imsmanifest.xml
├── test/
│   └── my-test.xml            (imsqti_test_xmlv3p0)
├── items/
│   ├── question-01.xml        (imsqti_item_xmlv3p0)
│   └── question-02.xml        (imsqti_item_xmlv3p0)
└── media/
    ├── diagram.png
    └── audio-clip.mp3
```

The `imsmanifest.xml` at the root is mandatory. The `test/`, `items/`, and `media/` folders are a convention, not a requirement &mdash; files may sit anywhere in the archive as long as the manifest's `href` values point to their actual locations (using forward slashes, relative to the manifest).

## Example

<Example title="A minimal imsmanifest.xml for a package with one item">

```xml
<?xml version="1.0" encoding="UTF-8"?>
<manifest xmlns="http://www.imsglobal.org/xsd/imscp_v1p1"
          xmlns:imsqti="http://www.imsglobal.org/xsd/imsqtiasi_v3p0"
          identifier="MANIFEST-QTI-1">
  <metadata>
    <schema>QTIv3.0 Package</schema>
    <schemaversion>1.0.0</schemaversion>
  </metadata>
  <organizations/>
  <resources>
    <resource identifier="question-01"
              type="imsqti_item_xmlv3p0"
              href="items/question-01.xml">
      <file href="items/question-01.xml"/>
      <file href="media/diagram.png"/>
    </resource>
  </resources>
</manifest>
```

</Example>

A package containing a test adds a second resource of type `imsqti_test_xmlv3p0` whose XML references the item resources it includes, plus a `<file>` entry per referenced media asset.
