Metadata describes what an item or test is, who made it, and how it can be used. It lets tools index, search, filter, and reuse resources in a bank without opening the underlying XML.

## Purpose

Attach descriptive information to the resources in a content package so that authoring tools, item banks, and delivery systems can discover and reuse them. QTI 3.0 draws on two complementary vocabularies:

- **IEEE LOM (Learning Object Metadata)** — general-purpose educational metadata, organised into categories such as:
  - *general* (title, description, keywords, language),
  - *lifecycle* (version, contribute roles like author and publisher),
  - *educational* (typical age range, difficulty, learning context),
  - *technical* (format, required tools or players).
- **QTI-specific metadata** — properties meaningful to assessment resources, for example the interaction types used, whether the item is *time dependent*, whether it is built from an item *template*, the *tool vendor*, and the *composite* or *feedback* characteristics.

Use metadata whenever items and tests need to be organised, searched, or exchanged between systems rather than authored and delivered in isolation.

## Place in the hierarchy

Metadata is not a QTI body element; it lives alongside packaging rather than inside the item's `qti-assessment-item`. It can appear in two places:

- **Resource metadata in the manifest** — inside a `<metadata>` element of a `<resource>` in `imsmanifest.xml`. This is the most common location and is what tools read when scanning a package.
- **Accompanying metadata files** — separate XML files referenced from the manifest, used when the metadata record is large or maintained independently.

Because QTI-specific and LOM elements come from their own namespaces, a manifest that carries metadata declares those namespaces at the top of the file.

Metadata is expressed through nested elements rather than attributes on a single QTI element. The table below lists the main information groups an authoring or discovery tool typically populates.

## Example

A resource entry in the manifest carrying both QTI-specific and LOM metadata. The example is trimmed to the essentials.

<Example title="Resource metadata inside imsmanifest.xml">

```xml
<resource identifier="item-0001"
          type="imsqti_item_xmlv3p0"
          href="items/item-0001.xml">
  <metadata>
    <!-- QTI-specific metadata -->
    <qti:qti-metadata xmlns:qti="http://www.imsglobal.org/xsd/imsqtiasi_metadata_v3p0">
      <qti:interaction-type>choice-interaction</qti:interaction-type>
      <qti:time-dependent>false</qti:time-dependent>
      <qti:tool-vendor>example.com</qti:tool-vendor>
    </qti:qti-metadata>

    <!-- IEEE LOM metadata -->
    <lom:lom xmlns:lom="http://ltsc.ieee.org/xsd/LOM">
      <lom:general>
        <lom:title>
          <lom:string language="en">Capital of France</lom:string>
        </lom:title>
        <lom:keyword>
          <lom:string language="en">geography</lom:string>
        </lom:keyword>
      </lom:general>
      <lom:educational>
        <lom:difficulty>
          <lom:value>easy</lom:value>
        </lom:difficulty>
      </lom:educational>
    </lom:lom>
  </metadata>

  <file href="items/item-0001.xml"/>
</resource>
```

</Example>
