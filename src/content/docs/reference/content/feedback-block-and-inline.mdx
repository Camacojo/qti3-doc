`qti-feedback-block` and `qti-feedback-inline` embed feedback **inside the
[item body](/concepts/item-body/)** rather than in a separate dialog. They use
the same outcome-driven mechanism as [`qti-modal-feedback`](/reference/content/modal-feedback/)
(which differs in more than placement: its `show-hide` is required and it has a
`title` attribute). The two body-level variants are:

- **`qti-feedback-block`** — block-level feedback (its own paragraph or region).
- **`qti-feedback-inline`** — inline feedback within a line of running text.

## When to use which

- Reveal a worked step next to the interaction → **feedback block**.
- Insert a short correction inside a sentence → **feedback inline**.
- Show an after-the-fact summary in a dialog → [modal feedback](/reference/content/modal-feedback/).

## Attributes

Both elements share the same attributes (unlike `qti-modal-feedback`, where
`show-hide` is required and a `title` attribute is available):

<AttributesTable shared attributes={[
  { name: 'outcome-identifier', type: 'identifier', required: true, description: 'The outcome variable whose value selects this feedback.' },
  { name: 'identifier', type: 'identifier', required: true, description: 'The value the outcome must hold for this feedback to show.' },
  { name: 'show-hide', type: 'show | hide', default: 'show', description: 'Whether a match shows or hides the content.' },
]} caption="qti-feedback-block / qti-feedback-inline attributes" />

## Example

<Example title="Block feedback revealed inside the body">
```xml
<qti-item-body>
  <!-- interaction here -->
  <qti-feedback-block outcome-identifier="FEEDBACK" identifier="EXPLAIN" show-hide="show">
    <qti-content-body>
      <p>The Amazon carries more water than the next seven largest rivers combined.</p>
    </qti-content-body>
  </qti-feedback-block>
</qti-item-body>
```
</Example>

Note the asymmetry: `qti-feedback-block` requires its content to be wrapped in a
`qti-content-body` element, while `qti-feedback-inline` takes inline content
directly.
