An **assessment stimulus** (`qti-assessment-stimulus`) is a standalone piece of
content — a reading passage, a diagram, a data table — authored once and shared
by several [items](/concepts/assessment-item/). It keeps a shared passage in a
single place instead of duplicating it into every item that uses it.

:::note
Renderer support for standalone stimulus resources varies; `@citolab/qti-components`
does not register a dedicated stimulus element at the time of writing. The
concept and packaging below are standard QTI 3.0.
:::

## Purpose

Use a stimulus when a group of items share the same source material:

- A reading comprehension passage answered by several questions.
- A shared chart, map or dataset interpreted by multiple items.

Editing the stimulus once updates it for every item that references it.

## Place in the hierarchy

- A stimulus is a **top-level resource**, structurally similar to an item but with
  no interaction. Its content lives in a `qti-stimulus-body`.
- It is packaged as its own resource in the
  [content package](/reference/packaging/content-package/) and referenced by the
  items (or the test) that use it, so delivery presents the passage alongside
  those items.
- Inside an item, the reference is made with the `qti-assessment-stimulus-ref`
  element — a direct child of `qti-assessment-item` that points at the stimulus
  by `identifier` and `href`. The manifest additionally records the relationship
  as a resource dependency.

## Example

<Example title="A shared reading passage">
```xml
<qti-assessment-stimulus
  xmlns="http://www.imsglobal.org/xsd/imsqtiasi_v3p0"
  identifier="passage-amazon" title="The Amazon river">
  <qti-stimulus-body>
    <p>The Amazon is the largest river in the world by discharge volume…</p>
  </qti-stimulus-body>
</qti-assessment-stimulus>
```
</Example>

In the package manifest the stimulus is its own resource; items that use it list
it as a dependency.
