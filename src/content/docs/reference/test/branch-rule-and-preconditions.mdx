`qti-branch-rule` and `qti-pre-condition` add conditional flow to a **linear**
test (they have no effect when navigation is `nonlinear`). Both evaluate an
[expression](/reference/processing/expressions/) — typically against an
[outcome variable](/concepts/outcomes-and-scoring/) — to decide what happens next.

## qti-pre-condition — skip if false

A precondition guards an element. If its expression evaluates to `false`, the
[section](/reference/test/assessment-section/) or
[item](/reference/test/assessment-item-ref/) it belongs to is skipped.

## qti-branch-rule — jump if true

A branch rule names a `target`. If its expression is `true`, delivery jumps to
that target instead of continuing in sequence. Targets can be a section, an item
reference, or the special values `EXIT_SECTION`, `EXIT_TESTPART`, `EXIT_TEST`.

## Example

<Example title="Branch to a remedial section on a low score">
```xml
<qti-assessment-item-ref identifier="diagnostic" href="items/diagnostic.xml">
  <qti-branch-rule target="remedial">
    <qti-lt>
      <qti-variable identifier="SCORE"/>
      <qti-base-value base-type="float">0.5</qti-base-value>
    </qti-lt>
  </qti-branch-rule>
</qti-assessment-item-ref>
```
</Example>
